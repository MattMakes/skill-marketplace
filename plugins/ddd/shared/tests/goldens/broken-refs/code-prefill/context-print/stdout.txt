# Billing (`billing`) — generic, pattern **transaction-script**, sourcing buy
Deployable `app` (modular-monolith, data store own) · team `solo` · canvas
  `ddd/07-define/billing/bounded-context-canvas.md`
Aggregates needed: **NO — use cases + persistence only**. Purpose: Billing takes the money for a chosen week:
  whenever meals are chosen it charges the household's card through Stripe and tells the rest of the system
  the week is paid. It owns no product rules — a failed charge is reported back to subscriptions, which
  decides what to do. Domain roles: execution-context. Scenarios: S1.
Subdomains: `billing` generic/transaction-script — Charging a card weekly is a solved problem (Stripe,
  commodity evolution); it moves no goal on its own, so buy the provider and keep our side a transaction scri…
