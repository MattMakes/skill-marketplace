# supply-chain-auditor — Python catalog

> Inlined into the supply-chain-auditor system prompt when the audited repo's primary language is `python`. Every entry below is a concrete pattern to look for in Python dependency manifests, lock files, install scripts, and CI config.

## File globs to scan

- `**/requirements*.txt`, `**/requirements-*.txt`, `**/requirements/**/*.txt`
- `**/constraints*.txt`
- `**/pyproject.toml`
- `**/Pipfile`, `**/Pipfile.lock`
- `**/poetry.lock`, `**/uv.lock`, `**/pdm.lock`
- `**/setup.py`, `**/setup.cfg`
- `**/conda-environment*.y*ml`, `**/environment.y*ml`
- `**/Dockerfile*` (look for `pip install` invocations)
- `**/.github/workflows/*.y*ml`, `**/.gitlab-ci.yml`, `**/azure-pipelines*.yml`
- `**/tox.ini`, `**/noxfile.py`
- `**/MANIFEST.in`
- `**/.pre-commit-config.yaml`

## Native tooling (run when available)

- `pip-audit -r requirements.txt` — official PyPA vulnerability scanner backed by the OSV + PyPI advisory database
- `pip-audit` (no args) — audits the active environment
- `safety check --full-report` — alternative scanner (uses Safety DB / pyup.io feed)
- `bandit -r .` — Python AST static analysis (overlaps with OWASP catalog)
- `pip list --outdated --format=json` — surfaces drift
- `pip-licenses --format=json` — license inventory (legal/risk)
- `cyclonedx-py requirements -i requirements.txt -o sbom.json` — generate SBOM
- `osv-scanner --lockfile=poetry.lock` — Google's OSV scanner supports Poetry lockfiles

## Risk patterns

### Unpinned dependencies

**What to look for:** entries in `requirements.txt` / `pyproject.toml` without exact version pins. `requests` (no version), `requests>=2`, `requests~=2.31` are progressively safer but still allow drift.
**Why it's risky in Python:** `pip install` resolves to the latest matching version at install time — the same `requirements.txt` produces different binaries across builds, opening a window for a malicious or buggy release to slip in.
**Concrete grep / ripgrep query:**
```
rg -nP "^(?!#|--|\s*$)([A-Za-z0-9_.-]+)(?:\[[^\]]+\])?\s*$" -g 'requirements*.txt' -g 'constraints*.txt'
rg -nP "^[A-Za-z0-9_.-]+(?:\[[^\]]+\])?\s*[><~^!]=?[^=]" -g 'requirements*.txt'
```
**File hint:** `requirements.txt`, `requirements/base.txt`, `requirements/dev.txt`.
**False-positive guard:** When a `constraints.txt` or hash-pinned lockfile (`requirements.lock`, `poetry.lock`) is also present and used at install (`pip install -r requirements.txt -c constraints.txt`), unpinned upper-level constraints are acceptable.

### `pyproject.toml` dependencies — Poetry/PDM/uv flexible specifiers

**What to look for:** caret (`^1.2.3`) and tilde (`~1.2.3`) ranges in `[tool.poetry.dependencies]`, PEP 621 `[project.dependencies]` with `>=` only.
**Concrete grep / ripgrep query:**
```
rg -nP "^[A-Za-z0-9_.-]+\s*=\s*[\x27\"]\s*[\^~][0-9]" -g 'pyproject.toml'
rg -nP "^\s*[\x27\"][a-zA-Z0-9_.-]+\s*>=\s*[0-9][^\x27\"]*[\x27\"]\s*,?\s*$" -g 'pyproject.toml'
rg -nP "python\s*=\s*[\x27\"][\^~]" -g 'pyproject.toml'
```
**File hint:** Poetry `[tool.poetry.dependencies]`, PEP 621 `[project.dependencies]`, PDM `[tool.pdm]`.
**False-positive guard:** Library projects (publishing to PyPI) need ranges so consumers can resolve — flag only application repos (those with `[tool.poetry] package-mode = false` or no `setup.py`/`build-system` for distribution).

### Missing or stale lockfile

**What to look for:** `pyproject.toml` with Poetry/PDM/uv blocks but no matching `poetry.lock`/`pdm.lock`/`uv.lock`; `Pipfile` with no `Pipfile.lock`; lockfile older than manifest (mtime check).
**Concrete grep / ripgrep query:**
```
rg --files -g 'poetry.lock' -g 'pyproject.toml'        # check both exist
rg --files -g 'Pipfile' -g 'Pipfile.lock'
rg --files -g 'uv.lock' -g 'pdm.lock'
```
**File hint:** Run `git log -1 --format=%cI <file>` on both manifest and lockfile and compare.
**False-positive guard:** Library packages distributed via PyPI rarely commit lockfiles — applications always should.

### `requirements.txt` without `--hash` pins

**What to look for:** absence of `--hash=sha256:...` lines after each requirement. Hashed pins guarantee binary reproducibility.
**Concrete grep / ripgrep query:**
```
rg -nP "^[A-Za-z0-9_.-]+==[0-9][^\s]*\s*$" -g 'requirements*.txt'
rg -nP "^--hash=sha256:" -g 'requirements*.txt' -c
```
**File hint:** Generated by `pip-compile --generate-hashes` (pip-tools) or `poetry export -f requirements.txt --output requirements.txt` (omits hashes by default — must add `--without-hashes=false`).
**False-positive guard:** None — hashes should be present whenever packages are installed in CI for production builds.

### `pip install` without `--require-hashes` in CI

**What to look for:** Dockerfiles / GitHub Actions running `pip install -r requirements.txt` without `--require-hashes`, even when the file contains hashes.
**Concrete grep / ripgrep query:**
```
rg -nP "pip install -r requirements" -g 'Dockerfile*' -g '*.y*ml' -g '*.sh'
rg -n "require-hashes" -g 'Dockerfile*' -g '*.y*ml' -g '*.sh' -g 'Makefile*'
```
**File hint:** `Dockerfile`, `.github/workflows/ci.yml`, `Makefile`, `tox.ini`.
**False-positive guard:** `pip install --require-hashes -r requirements.txt` or the equivalent `pip install --no-deps` flow.

### Dependency-confusion / private-package shadowing

**What to look for:** internal package names that could be claimed on public PyPI. Custom `--extra-index-url` / Poetry `secondary = true` source whose packages have unexceptional names.
**Concrete grep / ripgrep query:**
```
rg -nP "extra-index-url\s*=\s*https?://" -g 'pip.conf' -g 'pip.ini' -g 'requirements*.txt' -g 'Dockerfile*'
rg -nP "[\[(]tool\.poetry\.source[\])]" -g 'pyproject.toml'
rg -nP "secondary\s*=\s*true" -g 'pyproject.toml'
rg -nP "priority\s*=\s*[\x27\"]supplemental[\x27\"]" -g 'pyproject.toml'
```
**File hint:** `pyproject.toml` `[[tool.poetry.source]]`, `pip.conf`, internal `requirements/private.txt`.
**False-positive guard:** Poetry `priority = "explicit"` (PEP 708 style) ensures the package is only resolved from that index. Pinning the index per dependency (Poetry `source = "internal"`) is also safe.

### Typosquats — packages similar to popular ones

**What to look for:** common typosquat targets and homoglyphs.
**Concrete grep / ripgrep query:**
```
rg -nP "^(?:requesst|reqeusts|requests-)" -g 'requirements*.txt' -g 'pyproject.toml' -g 'setup.py'
rg -nP "^(?:urllib3-|django-)?" -g 'requirements*.txt'  # browse manually
rg -nP "^(?:python-?dateutil2|python-future-|cryptografy|crytography|pyjwt-|pyttsx)" -g 'requirements*.txt' -g 'pyproject.toml'
rg -nP "^(?:beautifulsoup|colourama|jellyfish-|sklearn\b)" -g 'requirements*.txt'   # 'sklearn' is the historic typosquat / soft-deprecated stub for scikit-learn
```
**File hint:** Cross-reference suspicious package names against PyPI download counts — extreme imbalance vs the legitimate package is a red flag.
**False-positive guard:** Manually verify each suspicious entry against `pypi.org/project/<name>/` (look at maintainers, release history, repo link).

### Packages with native build steps / arbitrary `setup.py` execution

**What to look for:** dependencies on packages without wheels — install runs `setup.py` arbitrary code. Worse if `--no-binary :all:` is used.
**Concrete grep / ripgrep query:**
```
rg -nP "no-binary\s*=\s*:all:" -g 'requirements*.txt' -g 'pip.conf'
rg -nP "pip install .*--no-binary" -g 'Dockerfile*' -g '*.sh' -g '*.y*ml'
```
**File hint:** Common for `cryptography`, `lxml`, `psycopg2` (vs `psycopg2-binary`), `numpy`, `pyyaml`, `pillow`. Trust-on-first-use for the build-time C compiler stage.

### Wheel-vs-sdist trust: packages that ship arbitrary `setup.py`

**What to look for:** packages installed from sdist where a wheel exists. `pip install --only-binary :all: <pkg>` is the safer install.
**Concrete grep / ripgrep query:**
```
rg -nP "only-binary\s*=" -g 'requirements*.txt' -g 'pip.conf' -g 'Dockerfile*'
```

### `setup.py` with `install_requires` that runs network calls

**What to look for:** `setup.py` that imports the package being built (chicken-and-egg), runs `subprocess` to download things, or uses `pkg_resources` dynamically — all execute on `pip install` of the source.
**Concrete grep / ripgrep query:**
```
rg -nP "(?:requests|urllib|subprocess|os\.system|wget)" -g 'setup.py'
rg -n "import [a-z_][a-z0-9_]*  # the package itself" -g 'setup.py'
```
**File hint:** Especially in dependency packages — if a flagged repo is itself published, this is a smell.

### Editable / VCS / local-path / direct-URL installs

**What to look for:** `-e .`, `-e git+https://...`, `git+ssh://...`, `file://...`, direct URL install (`pkg @ https://...`). Easy to ship malicious code outside PyPI's audit trail.
**Concrete grep / ripgrep query:**
```
rg -nP "^(?:-e\s+)?git\+(?:https?|ssh)://" -g 'requirements*.txt' -g 'pyproject.toml'
rg -nP "@\s*(?:git\+|file:|https?://)" -g 'pyproject.toml' -g 'requirements*.txt'
rg -nP "^-e\s+\." -g 'requirements*.txt'
```
**File hint:** Especially flag VCS installs without a commit SHA pin (`@<sha>` after the URL).

### `pip install` of arbitrary scripts via curl-pipe

**What to look for:** `curl ... | python`, `wget -O- ... | python`, `pip install $(curl ...)` patterns in install docs / Dockerfiles.
**Concrete grep / ripgrep query:**
```
rg -nP "curl\s+[^|]*\|\s*(?:python|pip)" -g 'Dockerfile*' -g '*.sh' -g '*.md' -g '*.y*ml'
rg -nP "wget\s+-[Oqs]+-?\s+[^|]+\|\s*(?:python|pip)" -g 'Dockerfile*' -g '*.sh'
```

### Outdated Python runtime base image

**What to look for:** Dockerfiles pinned to EOL Python (3.7 EOL 2023-06, 3.8 EOL 2024-10, 3.9 nearing EOL).
**Concrete grep / ripgrep query:**
```
rg -nP "^FROM\s+python:3\.[0-9](?![0-9])" -g 'Dockerfile*'
rg -nP "^FROM\s+python:(?:3\.7|3\.8|3\.9|2\.7)" -g 'Dockerfile*'
```

### GitHub Actions `setup-python` without SHA pin

**What to look for:** `uses: actions/setup-python@v5` (tag) instead of `uses: actions/setup-python@<sha>` (commit). Tags are mutable.
**Concrete grep / ripgrep query:**
```
rg -nP "uses:\s+actions/setup-python@v\d" -g '.github/workflows/*'
rg -nP "uses:\s+pypa/gh-action-pip-audit@v\d" -g '.github/workflows/*'
```
**False-positive guard:** SHA pins look like `@a1b2c3d4...` (40 hex chars).

### `bandit`/`safety`/`pip-audit` not present in CI

**What to look for:** absence of supply-chain scanning steps in CI configs.
**Concrete grep / ripgrep query:**
```
rg -nP "(?:pip-audit|safety|bandit|osv-scanner)" -g '.github/workflows/*' -g '.gitlab-ci.yml' -g 'azure-pipelines*.yml' -g 'Jenkinsfile*' -g 'Makefile*' -g '.pre-commit-config.yaml'
```
**File hint:** Lack of any hit indicates no automated supply-chain check.

### Conda/pip mixing without pinning

**What to look for:** `environment.yml` mixing `pip:` block with `conda` deps but neither lockfile (no `conda-lock` artifact). Resolution order matters and is fragile.
**Concrete grep / ripgrep query:**
```
rg -n "^\s*-\s*pip:" -g 'environment*.y*ml'
rg --files -g 'conda-lock.yml' -g 'conda-linux-64.lock'
```

### Yanked packages (manifest references known-bad versions)

**What to look for:** versions known to be yanked from PyPI (PyYAML 6.0 had a brief yank, `cryptography 35.0.0` had a critical CVE etc.). Run `pip-audit` or check `pip index versions <pkg>` output for `(yanked: ...)` markers.
**Concrete grep / ripgrep query:**
```
# No grep — invoke `pip-audit -r requirements.txt -f json` and parse output
```

### Internal package distribution metadata

**What to look for:** internal projects publishing to public PyPI by accident — `setup.py` `classifiers` not limited, no `Private :: Do Not Upload`.
**Concrete grep / ripgrep query:**
```
rg -nP "classifiers\s*=" -g 'setup.py' -g 'setup.cfg' -g 'pyproject.toml'
rg -nP "Private\s*::\s*Do Not Upload" -g 'setup.py' -g 'setup.cfg' -g 'pyproject.toml'
```
**False-positive guard:** Internal packages SHOULD include `"Private :: Do Not Upload"` classifier — its absence on an internal package is the finding.

### `Pipfile.lock` generated with `--pre` (pre-release) installs

**What to look for:** `pipenv install --pre` or `pip install --pre` enabling alpha/beta wheels.
**Concrete grep / ripgrep query:**
```
rg -n "\"_meta\"" -g 'Pipfile.lock'   # then look at hashes/metadata
rg -nP "pipenv install.*--pre|pip install.*--pre" -g 'Dockerfile*' -g '*.sh' -g '*.y*ml'
```

### Vendored dependencies stale / unpatched

**What to look for:** `vendor/`, `third_party/`, `deps/` directories committed with packages but no provenance.
**Concrete grep / ripgrep query:**
```
rg --files -g 'vendor/**/*.py' -g 'third_party/**/*.py' -g '_vendor/**/*.py'
```

### `MANIFEST.in` / `package_data` shipping secrets

**What to look for:** wheel-build configuration that includes `.env`, test fixtures, or config files in the published distribution.
**Concrete grep / ripgrep query:**
```
rg -nP "include\s+(?:\.env|.*\.pem|.*credentials.*)" -g 'MANIFEST.in'
rg -nP "package_data\s*=\s*\{" -g 'setup.py' -g 'setup.cfg'
```
