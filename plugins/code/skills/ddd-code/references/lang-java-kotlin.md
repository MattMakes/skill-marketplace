# Java / Kotlin — what differs

- **Value objects**: Java `record` with validation in the compact constructor; Kotlin `data class` (multi-field) or `@JvmInline value class` (single-field ids: `value class RecipeId(val value: String)`). Never a `typealias` for ids — it is not a distinct type.
- **Aggregate root / entities**: private fields / Kotlin `var … private set`; command methods; entity equality by id; JPA needs a protected no-arg constructor — keep JPA annotations out of the domain by mapping in the adapter (or accept jMolecules/JPA annotations as the one documented exception). Children exposed as `List.copyOf` / Kotlin read-only `List`.
- **Domain events**: Java records / Kotlin `sealed interface SubscriptionEvent` with `data class` cases. Spring: `AbstractAggregateRoot.registerEvent()` publishes on `repository.save()`; **Spring Modulith** adds an event-publication registry (redelivery) and `@ApplicationModuleListener` (after-commit, async) — that is your outbox. jMolecules annotations (`@AggregateRoot`, `@ValueObject`, `@DomainEvent`) keep the model framework-free and let ArchUnit verify it.
- **Ports**: interfaces in the context's `domain`/`application` package; Spring Data implementations in `internal`/`infrastructure`. One top-level package per context (Spring Modulith: everything under `<context>.internal` is hidden from other modules).
- **Dependency rule tooling**: ArchUnit (`noClasses().that().resideInAPackage("..domain..").should().dependOnClassesThat().resideInAnyPackage("..adapters..", "org.springframework..", "jakarta.persistence..")`; or `onionArchitecture()` DSL), Spring Modulith `ApplicationModules.of(App.class).verify()`; both are JUnit tests.
- **Tests**: JUnit 5 + AssertJ (Kotlin: Kotest); `shouldRejectChoosingTheSameWeekTwice`; `@ApplicationModuleTest` with `PublishedEvents`/`Scenario` for use-case-level event assertions.
- **Layout (one context)**: `<project>/<context>/{<Root>.java, <ValueObject>.java, <Context>Api.java (driving port), internal/{<UseCase>.java, <Repository>.java, <JpaRepository>.java, <Controller>.java}}` (Modulith style) or explicit `domain/application/adapters` packages; Gradle/Maven module per deployable.
