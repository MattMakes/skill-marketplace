# C# / .NET — what differs

- **Value objects**: `record` / `readonly record struct` (value equality, `with`); validate in the constructor; ids as `readonly record struct RecipeId(Guid Value)`. EF Core 8+: map value objects as **complex types** (`ComplexProperty`) rather than owned entities.
- **Aggregate root / entities**: `{ get; private set; }` or private fields; command methods (`subscription.ChooseMeals(week, recipes, clock)`); children as `IReadOnlyCollection<T>` over a private `List<T>`; `uint Version` with EF's `IsRowVersion()` for optimistic concurrency; parameterless private constructor for EF.
- **Domain events**: `record MealsChosen(...) : IDomainEvent`; collected on an `Entity` base (`AddDomainEvent`); dispatched from `SaveChangesAsync` (before commit = same transaction, after = eventual) — hand-roll a small dispatcher or use MassTransit/Wolverine; note MediatR went commercial in 2025.
- **Ports**: interfaces (`ISubscriptionRepository`, `IEventPublisher`, `IPaymentGateway`) in `<Project>.<Context>.Domain` or `.Application`; implementations in `.Infrastructure`. Project references enforce direction: Domain references nothing; Application → Domain; Infrastructure → Application; Api → all.
- **Dependency rule tooling**: NetArchTest (`Types.InAssembly(domain).ShouldNot().HaveDependencyOnAny("Microsoft.EntityFrameworkCore", "…Infrastructure")`) or ArchUnitNET, as xUnit tests; project split does most of the work.
- **Tests**: xUnit + FluentAssertions; `ChooseMeals_WhenWeekAlreadyChosen_ThrowsDomainException` or the sentence style (`Rejects_choosing_the_same_week_twice`); in-memory repositories in a `TestDoubles` project; integration tests with Testcontainers.
- **Layout (one context)**: `src/<Project>.<Context>.Domain`, `.Application`, `.Infrastructure`, and the deployable host `src/<Deployable>.Api` (composition root, `Program.cs`, DI registrations, migrations); or folders with the same names inside one project for a small modular monolith.
