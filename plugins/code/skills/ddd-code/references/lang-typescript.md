# TypeScript / Node — what differs

- **Value objects**: class with `readonly` props, private constructor, static `create()` that validates and returns `Result<VO, Error>` (neverthrow) or throws a domain error; `equals()` compares props structurally (never `===`); `Object.freeze` the props. Branded types (`type RecipeId = string & { readonly __brand: "RecipeId" }`) for single-value ids.
- **Aggregate root / entities**: class with private state, public command methods returning the domain event(s) or a `Result`; children as `ReadonlyArray`; expose a `snapshot()`/`toState()` for the repository adapter rather than getters for everything. Keep a `version` for optimistic concurrency.
- **Domain events**: plain immutable objects (`{ type: "meals-chosen", …}` or classes) collected on the root (`pullEvents()`); the application service publishes them after `repository.save()` through the `EventPublisher` port — no framework needed.
- **Ports**: `interface SubscriptionRepository { get(id): Promise<Subscription | null>; save(s, expectedVersion): Promise<void> }` in `application/ports/driven`; adapters in `adapters/driven/persistence`. One interface per use case for driving ports (`ChooseMeals.execute(cmd)`).
- **Dependency rule tooling**: `dependency-cruiser` (`.dependency-cruiser.cjs`: forbid `^src/.*/domain` → `^src/.*/(adapters|application)` and any `node_modules` except pure libs) or `eslint-plugin-boundaries` (`element-types` domain/application/adapters). Run in `npm test`.
- **Tests**: Vitest or Jest, `*.test.ts` beside the code or under `tests/`; `describe("Subscription") > it("rejects choosing the same week twice")`; in-memory adapters live in `adapters/driven/**/InMemory*.ts` and are used by application tests.
- **Layout (one context)**: `src/<context>/{domain,application,adapters}` with `domain/<aggregate>/{<Root>.ts,<ValueObject>.ts,events.ts,errors.ts}`, `application/{commands,queries,policies,ports}`, `adapters/{driving/http,driven/{persistence,messaging,gateways}}`; composition root `src/main.ts` or `apps/<deployable>/src/main.ts`.
- **Framework note**: NestJS modules map 1:1 to contexts — keep decorators out of `domain/` (DTO classes with decorators belong to the HTTP adapter).
