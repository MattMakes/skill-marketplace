# Sources and provenance

This reference records the historical basis for the skill. The skill does not require network access, and these links are not dependencies. Page references use the source document's visible page or the inspected PDF index as stated.

## Stone Librande, “One-Page Designs”

- [Author-hosted GDC 2010 page](https://stonetronix.com/gdc-2010/)
- [Author-hosted PowerPoint](https://stonetronix.com/gdc-2010/OnePageDesigns.ppt)
- [Talk video](https://www.youtube.com/watch?v=E9_wLks1kAg)
- [GDC Vault session record](https://www.gdcvault.com/play/1012356/One-Page)

The talk contrasts long design bibles and fragmented wikis with inspectable visual models. It recommends a title, current date, whitespace, a main illustration, callouts, details, and notes at 23:23–24:29; the same anatomy appears on deck page 45. It presents feedback flows, storyboards, time-and-space maps, relationship diagrams, and matrices on deck pages 48–59 and at 25:32–36:27. It rejects false geometry while revising a consequence model at 36:27–43:18. It recommends printed, annotated iterations at 43:42–45:48 and rough early versions at 48:59–50:05.

The talk treats “one page” as one inspectable surface, not one fixed paper size or a mandatory whole-game summary. Examples use letter, legal, tabloid, tabletop, and plotter-sized surfaces at 14:07–23:06 and 41:23–41:46. Librande describes an all-encompassing whole-game view as an aspiration rather than a requirement at 50:17–50:38.

No author-hosted PDF of the slide deck was verified. Page citations refer to a locally inspected PDF derived from the author-hosted 72-slide PowerPoint. The video transcript ends during an audience question at 51:58.

## *Leisure Suit Larry's Casino* design document

- [Al Lowe's design-document page](https://allowe.com/games/game-designs.html)
- [Public PDF](https://allowe.com/gamedesign/Larry%27s%20Casino%20Design.PDF)

This 31-page development document moves from concept, audience, goals, modes, commercial context, and scope into numbered UI, location, game, state, audiovisual, and production details. PDF indices 3–6 cover the overview and goals. Indices 8–29 cover scene and state behavior. Indices 30–31 preserve audio, discarded ideas, unresolved issues, and tasks. The source demonstrates explicit goals, inherited systems, state ownership, reuse, economy, and visible unknowns. It does not prove final shipped behavior.

## *Grim Fandango* Puzzle Document

- [Grim Fandango Network download page](https://grimfandango.network/downloads/puzzle-document)
- [Public PDF](https://grimfandango.network/media/Grim_Fandango_Puzzle_Document.pdf)
- [Video Game History Foundation record](https://gamehistory.org/gallery/grim-fandango-puzzle-design-document/)

This 72-page April 1996 preproduction document organizes the proposed adventure into four years. Character rosters, dependency diagrams, location maps, cut-scenes, and 80 numbered puzzle entries show gating, parallel and convergent paths, spatial adjacency, object setup and payoff, and narrative progression. Representative structure and map evidence appears at PDF indices 3–6, 21–24, 36–39, and 52–55. Printed page 71 visibly leaves the final puzzle solution unresolved. The document is a plan, not proof of the shipped game's behavior.

## Chris Taylor game-design template

- [Runaway Studios repost page](https://www.runawaystudios.com/articles/chris_taylor_gdd.php)
- [Public DOCX repost](https://www.runawaystudios.com/articles/ctaylordesigntemplate.docx)

The 22-page outline asks about game overview, philosophy, differentiation, world, camera, engine, lighting, characters, UI, weapons, audio, story, victory, multiplayer, networking, persistence, saving, rendering, and world editing. Pages 6–8 cover overview questions; pages 9–17 cover world through single-player concerns; pages 18–22 cover multiplayer through appendices. Its conclusion permits reordering, omission, renaming, and extension, so this skill uses it as question coverage rather than a mandatory template.

The available DOCX is a 2015 repost or conversion that claims Chris Taylor's 1999 copyright. No primary-author file was verified. Treat its content attribution as useful but its file provenance as limited.

## Interpretation boundary

The historical documents provide evidence for useful questions and representations. They do not establish a universal format. Accessibility, privacy-aware analytics, safety and inclusion, operational resilience, and explicit playtest evidence in this skill are contemporary guidance, not claims from these sources.
