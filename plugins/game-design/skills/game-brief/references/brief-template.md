# Brief template and section guide

The brief is for a reader who has 2 minutes. Stone Librande's test applies: "Most people don't
read past the first page or screen" (Librande, "One-Page Designs", GDC 2010). So the first screen
(Pitch, Player fantasy, play-by-play) must sell the game on its own. Kinds of fun follow Marc
LeBlanc, "8 Kinds of Fun" (8kindsoffun.com), and MDA (Hunicke, LeBlanc and Zubek, 2004).

## Frontmatter

```yaml
---
date: 2026-01-31              # YYYY-MM-DD, the day the brief was written
aesthetics: [Discovery, Submission]   # the 2-3 target kinds of fun
deprioritized: [Challenge, Fellowship, Sensation, Fantasy, Narrative, Expression]
core_verb: tend
scope: three months solo
runners_up: ["Title A", "Title B"]    # from game-ideation; [] if none
art: placeholder              # placeholder | skipped
verdict: unreviewed           # the reader later sets keep | prototype | pass
rating:                       # left empty; the reader fills it
---
```

## Sections

| Section | Length | What makes it good |
|---|---|---|
| **Pitch** | 1–2 sentences | Says what the player does, where, and the twist. No adjectives like "innovative" or "unique". |
| **Player fantasy** | 2–3 sentences | Who the player gets to be and what that feels like, in second person ("You are…"). |
| **30-second play-by-play** | 4–8 numbered beats | Concrete moments with rough timestamps (0:00, 0:05…). A reader can picture the screen. |
| **Why it's fun** | one `###` subsection per target aesthetic | Each subsection: the experience goal, the moment it happens, and the mechanic that produces it. |
| **Comparable games** | 2–4 bullets | A real game title, what this brief borrows from it, and how it differs. |
| **Scope for a solo developer** | a short table or list | Content counts, systems, art needs, and a rough time estimate for one person. |
| **Risks** | 3–5 bullets | Design risks first (is the fun real?), then production risks. Each with a mitigation. |
| **Smallest prototype that tests the fun** | 3–6 bullets | The least that must be built to learn whether the target fun appears. Grey boxes are fine. States the question it answers and how to tell yes from no. |
| **Open questions** | bullets | What the design has not decided yet, plus every assumption made while writing. |
| **Designer's doubts** | one placeholder line | A later critique step fills it. Leave the placeholder exactly. |

## Rules of thumb

- Every claim of fun names a mechanic. "It's relaxing" is not enough; "no fail state and a
  90-second tide timer that only resets the board" is.
- The prototype is small. If it needs more than two weeks for one person, cut it down.
- Comparable games are real, published games. Never name living artists.
